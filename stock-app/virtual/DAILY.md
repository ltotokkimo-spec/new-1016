# Claude 虛擬自組 ETF：每日操作程序

使用者想觀察「照 Claude 建議操作」的效果：Claude 用虛擬資金每天自動操作（10/19 起 10 萬，10/21 使用者指示加碼到 50 萬），App 的「自組ETF → Claude 虛擬操作」顯示結果。
這份程序由每個交易日 16:40（台北）啟動的排程任務執行（10/27 起；三大法人約 15:00～16:00 公布，若還查不到當天的就用前一天並在說明註明）。全部用繁體中文。不是投資建議，只是模擬。

## 檔案
- 狀態檔：`stock-app/virtual/virtual-etf.json`（分支 `claude/ui-calculator-interface-t3x9kh`；App 從 raw.githubusercontent.com 讀它）
- 工具：`node --experimental-strip-types tools/virtual-etf.ts <指令> virtual/virtual-etf.json ...`（在 `stock-app/` 目錄執行；不用 npm install）
  - `show`：目前狀態　`fill <日期> <quotes.json>`　`close <日期> <quotes.json>`　`order <日期> <orders.json>`　`note <日期> <文字>`
- 價格一律用證交所資料工具（MCP，名稱類似 `get_realtime_quote`，收盤後回傳當天開高低收；上市、上櫃都可查）。這個環境連不到證交所網站，不要用 curl。

## 步驟（D = 今天，台北日期 YYYYMMDD）
1. 先 `git remote set-url origin https://github.com/ltotokkimo-spec/new-1016`（環境重啟後網址會被改掉），再 `git pull origin claude/ui-calculator-interface-t3x9kh`，再 `show` 看狀態。如果狀態的 `asOf` 已經是 D，代表今天做過了，直接結束。
2. 用 `get_realtime_quote` 查 0050 確認今天有交易（時間戳是今天）。沒交易（假日、颱風）就結束，不要改檔案。
3. **成交前一天的委託**：查所有 `pending` 代號與 0050 的今日開高低收，寫成 quotes.json，執行 `fill D quotes.json`。
4. **收盤**：查所有持股與 0050 的收盤（同樣的 quotes 格式），執行 `close D quotes.json`。工具會自動把收盤跌破停損價的持股排入明天開盤賣出。
5. **研究與決策**（重點，不用每天都交易）：
   - 對每檔持股：用 MCP 查最近的三大法人買賣超、重大訊息、月營收（每月 10 日前後公布），並上網搜尋最近 3 天新聞。
   - 判斷要不要賣出、減碼、加碼；也可以找新標的：照下面「衛星選新標的」的規則（外資連續買超、成交金額 ≥ 3 億，營收年增可加分）。
   - **配置改成「核心＋衛星」（使用者 10/21 同意；使用者不要 0050）**：落後 0050 的主因是組合沒有半導體／AI 權值股，且回測「剛轉強」20 天平均只有 +0.6%、勝率 46%。
     - 核心約 45%：大型權值股，目前是台積電 2330（約 25%）、鴻海 2317（約 10%）、台達電 2308（約 10%）。10/22 先買目標的 2/3；剩下的 1/3 在 KD 低檔黃金交叉或 10/24 收盤後（以先到者）補足。核心不因短線回檔換股，只有停損（約 −10%）或基本面轉壞才賣。
     - 衛星約 25%：照下面的選股規則挑個股，現有持股都算衛星。
     - 現金約 30%（見下面的資金水位）。
   - **資金水位（使用者 10/21 指定：平常 7 成股票、3 成現金，跌深加碼最多 9 成）**：每天收盤後都要做
     1. 用 `get_taiex_index_history` 查加權指數最近 20 個交易日的收盤，算「今天收盤距 20 日最高收盤」的跌幅（負數小數，例如 -0.071）。
     2. 執行 `cash D <跌幅> "一句話說明"`，工具自動決定目標：跌不到 5% → 7 成；跌 5% 起 → 8 成；跌 10% 起 → 9 成。至少留 1 成現金，永遠不超過 9 成。
     3. 用 `show` 看「資金水位」那行：股票比重低於目標就分批買進（每天最多加 10% 淨值，優先補核心，再補衛星；10/22 那批是加碼 40 萬後的第一次建倉，不受這個限制），高於目標就不買新股。
     4. 回到 7 成：加權指數收盤站回 20 日線、且距 20 日高點不到 3% 時，跌幅改填實際值讓目標回到 7 成；超出的部分分 2～3 天從「漲最多的衛星」減碼，不砍核心。
     5. 說明裡要寫一句水位：「股票 X%／目標 Y%（原因）」。
   - **衛星選新標的：外資連買＋大成交金額（使用者 10/22 指定，取代 10/19 的「剛轉強」）**。原因：2 年回測「剛轉強」20 日平均 +2.3% 低於全部股票的 +2.7%、贏過中位數只有 51%，沒有優勢；2 年因子分析裡成交金額大是最穩定的因子（20 日 IC +0.068）、外資連續買超有微弱正向。買進新標的前要同時符合：
    1. 外資連續買超 ≥ 3 個交易日（含今天），且近 5 日合計買超 > 0（用 `get_twse_institutional_investors_by_stock`，上櫃用 `get_otc_institutional`）。
    2. 當日成交金額 ≥ 3 億（約全市場前一半；App「自組ETF」候選股卡片寫的門檻每天會變，約在 3 億上下，這裡一律以 3 億為準）。
    3. 安全閥（不是進場訊號，只用來避免追高）：用 `get_technical_indicators` 查，收盤在 60 日線之上、RSI(14) 低於 75、近 1 週漲幅低於 15%。
    4. 投信買超**不加分**（2 年因子分析中投信是穩定的反向訊號）；同分時優先本益比、淨值比偏低的。
    5. 停損設在 20 日線或 60 日線下方、約 −5%。
    - 候選來源可以先看 App「選股」的「買入」篩選，或下載 `https://github.com/ltotokkimo-spec/new-1016/releases/download/stock-radar-data/scorecompare.json` 看 `shadow.latest.shadow`（影子評分 C 的買入名單，偏大型股且外資買超），再用 MCP 驗證上面幾條；不要只因為在名單裡就買。
    - 「剛轉強」不再是進場條件，只拿來看買進時機與停損位置。現有衛星持股（大成鋼、中鋼、儒鴻、潤泰新等）**不因規則改變而強賣**，照原本的停損與高檔回落規則處理；新規則只用在新買進。
    - 每次買進的 `reason` 要寫明「外資連買 N 天、成交金額 X 億」，週檢視才能和舊規則（剛轉強）的持股分開比較。
  - 持股若「高檔回落」（跌破 5 日線且 KD 在 70 以上死叉）就考慮減碼或換股，不要等到停損才走。
  - 衛星若「外資連續賣超 ≥ 3 天且收盤跌破 20 日線」（10/22 新增，與新的進場規則對稱）也考慮減碼或換股。
   - **觀察名單**（10/19 起，每天在說明裡用一句話追蹤有沒有走出來，約一週）：潤泰新 9945、中鋼 2002（已買進）、友達 2409（籌碼最強但波動大，站穩 20 日線且 MACD 翻正再考慮買）。
   - 規則：持股 6～10 檔（核心 3 檔＋衛星）、至少 3 個產業、單一檔不超過淨值 25%、現金依資金水位（平常約 3 成、最少 1 成）、零股以「股」為單位、買進都要給停損價；不追高（限價設在今天收盤價附近，最多 +1.5%）。
   - 避免過度交易：沒有明確理由就維持不變。單日換股不超過 2 檔。
   - 有要做的就寫 orders.json：`[{"code":"2330","name":"台積電","side":"buy","shares":10,"limit":1010,"stop":930,"reason":"一句話理由"}]`，執行 `order D orders.json`。賣出不用 limit。
6. **寫說明**：`note D "..."`（同一天的說明會被取代：如果 `show` 前當天已經有說明，例如使用者盤中調整，要把原本內容保留在前面，再接上收盤說明），2～4 句：今天組合表現與 0050 比較、明天要做什麼（或為什麼不動）、需要注意的風險。
7. `show` 檢查沒有錯（沒有負現金、沒有缺價）。然後只 `git add stock-app/virtual/virtual-etf.json`，commit 訊息「virtual-etf: D 收盤更新」，`git push origin claude/ui-calculator-interface-t3x9kh`（衝突就 `git pull --rebase` 再推，最多重試 4 次）。只改這個 JSON，不要改其他程式。
8. 發手機推播（PushNotification 工具），一行：「✅ 虛擬ETF D：淨值 X（+Y%），0050 +Z%；明天：…」。失敗就推「❌ 虛擬ETF D 更新失敗：原因」。
